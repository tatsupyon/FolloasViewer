FolloasViewer (画像VIEWER) システム仕様書

1. システム概要

本システムは、FolloasConverterで生成された _ViewReady フォルダを読み込み、GUI上で各種データの同期再生、位相調整、カット編集、および不要シーンを除外した再エンコード（エクスポート）を行うためのツールです。 最新バージョン: V1.67 (2026/09/13)

2. 動作環境・依存ライブラリ

  • Pythonバージョン: Python 3.14.4
  • 標準ライブラリ: os, csv, glob, time, threading, tkinter, shutil, tempfile, sys
  • 外部ライブラリ:
  • opencv-python (cv2): 画像の読み込み、動画のエクスポート
  • numpy: 画像データの配列処理、合成
  • Pillow (PIL): キャンバスへの描画、Tkinterへの画像渡し

3. 主要な内部仕様

  • データ構造 (Cut Flags):
  • 最大フレーム数分のブール値配列（cut_flags）でカット状態を管理。
  • START-END方式による範囲書き換え（ビットマップ方式）により、重複区間の競合を排除。
  • SCORE閾値管理:
  • tk.DoubleVar によるGUIとの双方向バインディング。
  • キャンバス描画から標準Widget（Entry）へ移行し、入力容易性を向上。
  • 日本語環境への最適化:
  • 出力される集計データ (output.csv) のエンコーディングを cp932 (Shift-JIS) に統一し、Excel等での閲覧性を確保。
  • viewer.ini のキー名を英字（ASCII）に統一し、実行環境やエンコーディングの違いによる読み込みエラーを完全に排除。
  • 描画仕様 (V1.06 オリジナル再現):
  • 使用フォント: Lucida Console (20pt) を標準採用。
  • 描画ピッチ: 横 14px / 縦 28px (fontpitchx2/fontpitchy2)。Viewing時もこのピッチで統一。
  • 文字色: 認識枠上のスコア、および解析画面上部のメッセージは全て 白 (#FFFFFF) で描画。
  • 動的配置: 認識枠が画面上端に近い場合、スコア表示を枠の下側に自動的に回り込ませる補正ロジックを搭載。
  • Live2表示仕様:
  • -no-compress-l2 起動引数、または「LIVE2圧縮なし」UIにより、Live2の画像アスペクト比を維持します。Live2画像から認識領域である中央の 400x720 をクロップし、720x720 にリサイズして表示します。
  • 学習画像エクスポート仕様:
  • 「学習画像エクスポート」機能は、現在表示中のLive2画像（上記仕様でクロップ・リサイズ済み）を _ViewReady/training フォルダに出力します。
  • 同時に、認識ログから枠座標を取得し、YOLOフォーマット (<class_id=0> <x_center> <y_center> <w> <h>) に正規化変換して、同名の .txt アノテーションファイルとして保存します。

4. viewer.ini 仕様

| キー名 | 内容 | 形式 | | :--- | :--- | :--- | | SCORE_THRESHOLD | 認識枠の判定基準 | float (例: 0.40) | | ANALYSIS_PHASE | ログデータのオフセット | int | | LIVE2_PHASE | Live2動画のオフセット | int | | SHOW_LIVE1_BOX | Live1画像上の枠表示 | ON / OFF | | CUT_RANGES | カットされた全区間 | [start,end,start,end...] のカンマ区切り |

5. エクスポート仕様 (_Edit フォルダ)

  • 動画: mp4v コーデックを使用。
  • スコア焼き込み: 解析画面およびLIVE1画面の認識枠上に、Viewing時と同様のスコア（白文字）を焼き込みます。
  • フレーム制御: カットされたフレームはインデックスレベルで完全にスキップされ、タイムスタンプが再計算されます。
  • ログ:
  • head.log: 1フレーム1行の基本情報に加え、物体検出時に @@@ 行を挿入。
  • head2.csv: 重複のないクリーンなフレームヘッダー形式。
  • output.csv: run_summarize_log 関数による自動集計結果。
  • 同期整合性: 基準フレーム j に対して j + off_log および j + off_l2 を参照。セット単位でカット判定を行うため、同期ズレは発生しません。
